# Mengshee 2026.0.22.4

## Restore PDF font rendering semantics

- Remove the local paint-time Unicode font override and restore Poppler's PDF encoding-to-glyph rendering path, rather than adding character-specific exceptions.
- Bundle the complete set of 14 standard substitute fonts in the Windows core installer, including Symbol and ZapfDingbats. No additional font or StemTeX installation is required. Fonts embedded in the PDF remain authoritative.
- Substitute missing simple fonts according to family, bold, and italic attributes. Identify external fonts by their actual program format and preserve font-collection face indices.
- Fix font-resource lookup in installation paths containing non-ASCII characters and use consistent font sources for glyph bounds and painting.

## Validation

- Packaged-runtime font tests: 66 passed, 0 failed, 0 skipped. Glyph-bounds tests: 4 passed, 0 failed, 0 skipped. Counts include initialization and cleanup.
- Coverage includes Standard 14, Encoding/ToUnicode, embedded CFF, horizontal and vertical CIDToGID mappings, Type3, Symbol/Zapf glyphs and widths, missing-font styles, and existing annotation AP save/reload roundtrips.
- Real-document visual comparisons with PDFium, pixel-identical SDK/package output, Unicode-path relocation without SDK/TeX lookup, negative resource-integrity tests, and independent packaged-application startup all passed.
- No unrelated mode-switch matrix was run. The user's PDF and running installed application were not modified.

This release corrects rendering of existing PDFs; it does not rewrite complex-script layout or font embedding for newly authored FreeText annotations. See [PDF font rendering](https://github.com/zhaiyusci/mengshee/blob/master/docs/pdf-font-rendering.md) for the technical scope and audit findings.
