# Mengshee 2026.0.27.0

Large PDF pages now render only the requested visible region. MuPDF reuses page and annotation display lists while panning or zooming, and can cancel obsolete rendering requests in progress.

## Fixes

- Fix adding note pages failing on the last page because named destination page numbers were interpreted with the wrong index base.
- Wait for queued text extraction completion before removing or replacing pages, preventing a crash during note-page rollback or undo. Rebuild text-cache page indices after page topology changes.
- Correct numeric destinations when creating or editing internal and remote PDF links, and correct source page selection when importing PDF/template pages. Reject invalid link targets before changing the existing annotation.
- Share MuPDF context locks across the runtime and independent preview contexts. Invalidate cached annotation appearances after edits.

## Validation

87 QtTest checks passed, including page-index boundaries, saved/reopened link destinations, imported-page pixel comparisons, concurrent preview, cancellation and page lifecycle regression. The page lifecycle stress test reproduced an access violation with the previous core and passed after the fix.

On a synthetic 5 m square vector page, cached 1024 × 768 region rendering took about 20 ms versus about 2 s for an 8192 × 8192 full-page render. With 1024 annotations, reusing annotation display lists reduced subsequent region rendering from about 34 ms to 22 ms. These are backend measurements on one machine, not UI latency guarantees or scanned-document results.
