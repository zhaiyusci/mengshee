# Mengshee 2026.0.22.6

## PDF and Beamer animation

- Preserve PDF push-button appearances while forms are enabled. Native controls no longer cover animation frames or author-drawn button artwork.
- Make PDF push buttons interactive in presentation mode using the same controls and form-action handling as reading views. Animation controls no longer accidentally advance the slide; blank-page clicks still navigate.
- Show a pointing-hand cursor over clickable PDF buttons in reading and presentation views, while retaining presentation cursor-visibility settings.
- Keep existing presentation keyboard navigation, drawing tools, and media/toolbar stacking behavior.

These changes support JavaScript-driven PDF frame animation, such as Beamer documents made with the `animate` package. They do not enable embedded audio/video playback or promise compatibility with every PDF rich-media format.

## Upstream integration and reliability

- Merge Okular upstream through September 30, 2026 while retaining Mengshee's reading views, LaTeX annotations, native popup caret, font selection, and branding.
- Unify backend preferences with the main settings dialog and add F11 as a fullscreen shortcut.
- Include applicable upstream form-saving, script memory-safety, signature-panel, font-extraction, and SyncTeX fixes.
- Fix annotation undo identity after saving and replacing backend objects.
- Keep the existing Poppler and StemTeX versions. Multimedia and actual cryptographic signing remain disabled in this Windows build; newer eIDAS support is not enabled.

## Validation

- Packaged-runtime matrix: 23 test processes, 669 passed, 0 failed, 1 skipped (counts include setup/cleanup). The skip is the optional LaTeX fixture-export helper.
- Coverage includes visible animation frames, step/play/pause, repeated hand-cursor entry/exit, presentation navigation, form replicas, scripts, annotation save/undo, fonts, LaTeX appearances, native caret, reading views, and export.
- Tests ran with the staged application's own libraries and optional TeX tree, without SDK paths. Test-only executables were not packaged and were removed from the stage afterward.
- The packaged GUI opened a clean PDF and closed normally; the application, Core, Part, and PDF backend loaded from the package, not the SDK.
- The existing Windows tablet-proximity cursor assertion also fails in the previous trial build. It remains outside this accepted matrix and was not changed here.
