# Mengshee 2026.0.24.0

## Page size

- **Page Editing** mode can change the visible size of any page, note pages included. The page under the pointer shows handles on its four borders and four corners; dragging one moves those borders and leaves the opposite ones where they are, so the content keeps its position relative to the borders that stay put. A dashed preview follows the pointer, releasing applies the change, and one drag is one undo step. **Page Size…** in the page context menu — and the same button in the page-edit toolbar — performs the same operation with exact numbers and keeps the lower-left corner.
- The numbers are the page's own, unrotated width and height in PDF points, like the blank-page size in the page insertion dialog, so they keep their meaning on a rotated page.
- What a reader displays is the **crop box** when the page has one and the **media box** otherwise, so the operation moves that box rather than the media box alone, keeps its lower-left corner, and grows the media box when the new crop box would leave it, as the format requires. Both are written as the page's own entries, which override anything inherited through the page tree. A smaller size only hides what falls outside the visible box; nothing is deleted, so enlarging it again brings that back. `/Rotate` and `/UserUnit` are untouched, and sizes stay between 1 and 20000 points per side.
- Every handle in the application now agrees between what is drawn and what can be grabbed: the grab area is the painted rectangle including its pen, and the nearest handle wins when two overlap, so a corner is no longer taken by the border beside it. Hovering a page handle sets the matching resize cursor on the viewport, driven by the mouse events themselves.

## Link targets

- A link's target is no longer cached as a page number. An explicit destination remembers the **page object** it names, as an opaque identity, and the number is resolved when the target is needed; a named destination is resolved through the document's named viewports. Editing pages therefore cannot leave a link pointing at the wrong page: inserting, removing, moving, rotating or resizing pages leaves every link box, its rectangle and any selection exactly as they were.
- Renaming a named destination no longer clears anything. It rewrites the name in the file as before and rebuilds the link objects of the affected pages, because the actions spell the old name; their rectangles come from the same sources, so they do not move. Previously that step cleared every page's link objects and reported a full document change, which made every link box disappear and dropped the current selection.
- A link whose target page was removed now resolves to no target rather than to a wrong page. See [Link targets are resolved when they are needed](../link-targets.md).

## Messages and translations

- The page-size strings are translated: the action, the dialog and both hints in the size dialog, along with the messages the operation reports. The Chinese catalogue carries them, using the terminology the rest of it uses. The other catalogues pick the new strings up on the next translation sync.
- The status messages no longer end with a reminder to save the document. Twenty-odd of them did — rotating a page, deleting one, moving a link, adding a note page, recognising text and more — and the sentence said nothing: an edited document obviously has to be saved. It is gone from the messages and from the catalogue, so every one of them is shorter now.

## Annotations

- From the Poppler fork: generated annotation appearance bounds are preserved, and stamp content is clipped inside its frame.

## Building

- `windows-build\build-mengshee.cmd` builds, deploys and packages with the canonical driver and the paths already resolved. It has to run in a normal session: Ninja cannot start its compilers inside a session that confines the process tree and stalls forever on the first command, even `cmd /c echo`, while `ninja -n` still works. See `windows-build/README.md` and [The development runtime](../development-runtime.md).
- The optional StemTeX component is gated by its own TeX configuration (`StemTeX/runtime/texmf-dist/web2c/texmf.cnf`) instead of a runtime executable it does not contain, and the run-tree check reports what it actually found instead of assuming a label problem.
- The fork's work is kept on its `master` branch, so the gitlink this repository pins is normally the tip of that branch.

## Validation

- The changed translation units compile clean, and the full pipeline — build, deploy, package — finishes with exit code 0.
- The Chinese catalogue was compiled with `msgfmt --check` (1780 translated messages) and the new entries were read back out of the compiled result, along with the removal of the save reminder. The `okular.mo` the build installed and the one in the package stage both carry them, which is the file the application loads.
- The run-tree check reported the installed tree, the package stage, the optional StemTeX payload and the produced installer runnable with the rights of a normal user, reading the label back as `Medium`.
- The published copy in `output/releases/2026.0.24.0` is byte-identical to the one the packaging step produced, and `windows-build/scripts/make-release.ps1` verified and repaired its label.
- The page-box semantics were covered by a standalone check against the page editor: growing a page keeps its rendered content unchanged (the old rendering is the bottom-left part of the new one) and leaves the other pages alone, the media box keeps containing the crop box, shrinking only hides and enlarging again restores the original rendering exactly, and invalid sizes are rejected. All 29 checks passed; the box code has not changed since that run.
- Not run on this machine: `parttest`, which needs a session that can write the temporary tree a GUI test uses. The behaviour is covered by the cases added there: `testLinkTargetFollowsPages` (the link objects and their rectangles survive inserting a page, and an explicit destination still resolves to the same page content, before and after undo) and the live check in `testEditPdfNamedDestinationAndLink` (renaming a destination does not drop the page's link objects).
- The staged smoke test was not observed in this run's output, so this build makes no claim about it.
