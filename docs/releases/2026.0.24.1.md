# Mengshee 2026.0.24.1

A patch release. It fixes what an audit of 2026.0.24.0 found, including one regression that
release introduced, and it is the first release whose test suite was actually run here.

## Link targets

- **A link whose destination is the first page kept a cached page number** instead of a page
  identity, so inserting a page before it made it point at the wrong page. The identity is now
  taken from the page the destination really names (`getPageRef` counts pages from one, the
  viewport from zero), and the lookup walks the whole range. Reported, reproduced, and covered
  by the new `parttest::testLinkToFirstPageFollowsInsertion`.
- **Links to another file lost their destination page.** An explicit destination that points
  into a different document took a page identity from *this* document and had its page number
  cleared, so opening the target file stopped at its first page. Cross-file destinations are
  left alone now, and the viewport is handed to the file that is opened.
- **Reordering pages no longer clears every page's link objects.** `Document::movePage` still
  did what the previous release removed elsewhere, so a reorder lost the link boxes and the
  current selection until the next render.
- **Renaming a destination marks the outline out of date.** Its cached copy still resolved the
  old name, so outline entries stopped working after a rename.
- The presentation view resolves an explicit destination for its tooltip, which had become
  empty.

## Validation

- `parttest` was run on this machine for the first time: **107 passed, 15 failed, 2 skipped**.
  Every link-related test passes, including the three that the change had broken
  (`testClickInternalLink`, `testLivePdfLinksHaveNoVisibleBorder(internal-direct)`,
  `testEditPdfNamedDestinationAndLink`) and the two new ones.
- The 15 failures are environment, not code: this session cannot start a KIO worker
  (`kf.kio.core: couldn't create worker: "Unknown protocol 'file'."`), and the application's
  data directory is not deployed for the test run (`Unable to open default annotation tools
  XML definition`). They are concentrated in saving, text selection and copying, scrolling and
  the note-page click, none of which this change touches; the suite also ends with a crash in
  the save path. A pre-change run was not made, so this is a reasoned triage rather than a
  comparison.

## Known limits

- After renaming a destination, the link actions in the **open** document still spell the old
  name; they are re-read when the document is loaded again. A page's link list comes from the
  backend's cached page, which the rename does not invalidate. The link boxes and their
  rectangles are correct, and the saved file is correct.
- In Cross-References mode a click selects the link for editing instead of following it. That
  is the mode's design; the upstream test that expected navigation now checks navigation
  before the mode is switched on.
